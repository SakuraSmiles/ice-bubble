## 🧪 测试类型

### 1. 单元测试（Unit Tests）

**用途**: 测试独立的函数、类和方法

**位置**: `tests/unit/`

**运行方式**: 使用 Vitest

```bash
# 运行所有单元测试
npm test

# 运行特定测试文件
npx vitest run tests/unit/collectors/FileCollector.test.ts

# 监听模式
npm run test:watch
```

**命名规范**: `*.test.ts`

**示例**:
- `FileCollector.test.ts` - FileCollector 单元测试
- `BatchWriter.test.ts` - BatchWriter 单元测试
- `DataValidator.test.ts` - DataValidator 单元测试

---

### 2. 集成测试（Integration Tests）

**用途**: 测试多个模块协作

**位置**: `tests/integration/`

**运行方式**: 使用 Vitest

```bash
# 运行集成测试
npx vitest run tests/integration/
```

**示例**:
- `file-collector-integration.test.ts` - 文件采集器集成测试

---

### 3. 性能测试（Benchmark Tests）

**用途**: 测试性能和吞吐量

**位置**: `tests/benchmark/`

**运行方式**: 使用 Vitest bench

```bash
# 运行性能测试
npm run test:benchmark
```

---

### 4. 测试脚本（Test Scripts）

**用途**: 针对原生模块（如 better-sqlite3）的测试，使用 tsx 运行

**位置**: `tests/scripts/`

**运行方式**: 使用 tsx 直接运行

```bash
# SQLiteManager 测试
npm run test:sqlite

# FileCollector 测试
npx tsx tests/scripts/test-file-collector.ts
```

**为什么使用 tsx？**
- `better-sqlite3` 是原生 C++ 模块，与 Vitest 存在兼容性问题
- tsx 轻量级、快速、支持 TypeScript
- 适合测试原生模块

## 📊 测试输出管理

### 测试输出目录

**位置**: `tests/output/`

**用途**: 存放测试生成的临时文件和报告

**文件命名规范**（扁平化，不再分子目录）:
```
tests/output/
├── coverage-final.json      # 覆盖率报告（JSON 格式）
├── lcov.info               # 覆盖率报告（LCOV 格式）
├── index.html              # 覆盖率报告（HTML 格式）
├── junit.xml               # JUnit 报告（可选，用于 CI/CD）
└── benchmark-{date}.json   # 性能测试结果
```

**命名规范**:
- `coverage-*.{html,json,info}` - 测试覆盖率报告
- `junit-*.xml` - JUnit 格式报告
- `benchmark-*.json` - 性能测试结果
- `test-result-*.txt` - 其他测试输出

**版本控制**: ❌ 已加入 `.gitignore`，不进行版本控制

**清理方式**: 测试结束后自动清理，或手动清理：

```bash
# PowerShell
Remove-Item -Path tests\output -Recurse -Force

# Bash
rm -rf tests/output
```

## 🧩 添加新测试

### 添加单元测试

1. 创建测试文件: `tests/unit/{module}/{ClassName}.test.ts`

2. 编写测试用例:
```typescript
import { describe, it, expect, beforeEach, afterEach } from 'vitest';
import { YourClass } from '../../../src/your-module/YourClass';

describe('YourClass', () => {
  let instance: YourClass;

  beforeEach(() => {
    instance = new YourClass();
  });

  afterEach(() => {
    // 清理资源
  });

  it('should do something', () => {
    expect(instance.method()).toBe(expectedValue);
  });
});
```

---

### 添加集成测试

1. 创建测试文件: `tests/integration/{feature}-integration.test.ts`

2. 编写集成测试:
```typescript
import { describe, it, expect } from 'vitest';
import { ModuleA } from '../../src/module-a';
import { ModuleB } from '../../src/module-b';

describe('ModuleA + ModuleB Integration', () => {
  it('should work together', async () => {
    const moduleA = new ModuleA();
    const moduleB = new ModuleB();
    
    // 测试模块协作
    const result = await moduleA.process(moduleB);
    expect(result).toBeDefined();
  });
});
```

---

### 添加测试脚本

1. 创建测试脚本: `tests/scripts/test-{module}.ts`

2. 编写测试脚本:
```typescript
import { YourModule } from '../../src/your-module/YourModule';

async function main() {
  console.log('Starting test...');
  
  try {
    const module = new YourModule();
    // 测试逻辑
    console.log('✅ Test passed');
  } catch (error) {
    console.error('❌ Test failed:', error);
    process.exit(1);
  }
}

main();
```

3. 添加到 `package.json`:
```json
{
  "scripts": {
    "test:{module}": "tsx tests/scripts/test-{module}.ts"
  }
}
```

## 🐛 问题排查

### 测试失败

1. **检查依赖**: `npm install`
2. **检查 TypeScript**: `npm run typecheck`
3. **查看错误日志**: 测试输出会显示详细错误信息
4. **检查测试数据**: 确保 `tests/fixtures/` 中的数据正确

### 测试卡住

如果使用 Vitest 测试原生模块卡住：
- 改用 `tests/scripts/` + tsx 的方式
- 参考 `test-sqlite-manager.ts`

### 清理失败

如果测试输出未自动清理：

```bash
# PowerShell
Remove-Item -Path tests\output -Recurse -Force

# Bash
rm -rf tests/output
```
