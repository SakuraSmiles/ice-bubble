## 概述

### 设计目标

存储层负责持久化存储 OpenClaw 采集的所有数据，设计目标：

- ✅ **轻量化**: 内存占用 < 50MB
- ✅ **高性能**: 批量写入 > 5000 TPS
- ✅ **简单可靠**: 无复杂依赖，易于维护
- ✅ **嵌入式**: 无需独立数据库服务

## SQLiteManager 设计

### 类设计

```typescript
/**
 * SQLite 管理器
 * 
 * 职责：
 * - 数据库初始化和生命周期管理
 * - Session 和 Message 的 CRUD 操作
 * - 批量写入优化
 * - 数据清理和维护
 */
export class SQLiteManager {
    private db: Database | null = null;
    private dbPath: string;
    private isInitialized: boolean = false;
    
    // ========== 生命周期 ==========
    
    /**
     * 初始化数据库
     * - 创建数据库文件
     * - 创建表结构
     * - 启用 WAL 模式
     * - 创建索引
     */
    async init(config: SQLiteManagerConfig): Promise<void>;
    
    /**
     * 关闭数据库连接
     */
    async close(): Promise<void>;
    
    // ========== Session 操作 ==========
    
    /**
     * 插入或更新会话（upsert）
     * - 存在则更新 updated_at 和 message_count
     * - 不存在则插入新记录
     */
    async upsertSession(session: Session): Promise<void>;
    
    /**
     * 获取会话列表（分页）
     */
    async getSessionList(options?: {
        agentId?: string;
        limit?: number;
        offset?: number;
        orderBy?: 'updated_at' | 'created_at';
    }): Promise<Session[]>;
    
    /**
     * 获取单个会话
     */
    async getSession(sessionKey: string): Promise<Session | null>;
    
    // ========== Message 操作 ==========
    
    /**
     * 插入单条消息
     */
    async insertMessage(message: SessionMessage): Promise<number>;
    
    /**
     * 批量插入消息（核心性能方法）
     * - 使用事务批量插入
     * - 自动更新 session 的 message_count
     */
    async batchInsertMessages(messages: SessionMessage[]): Promise<number>;
    
    /**
     * 获取会话历史消息
     */
    async getSessionHistory(
        sessionKey: string, 
        options?: {
            limit?: number;
            beforeTimestamp?: Date;
        }
    ): Promise<SessionMessage[]>;
    
    // ========== 统计和维护 ==========
    
    /**
     * 获取统计信息
     */
    async getStats(): Promise<{
        totalSessions: number;
        totalMessages: number;
        dbSizeMB: number;
    }>;
    
    /**
     * 清理过期数据
     * - 删除指定天数前的数据
     * - 返回删除的记录数
     */
    async cleanOldData(daysToKeep: number): Promise<{
        sessionsDeleted: number;
        messagesDeleted: number;
    }>;
}
```

### 1. sessions 表（会话元数据）

```sql
CREATE TABLE sessions (
    session_key TEXT PRIMARY KEY,
    agent_id TEXT NOT NULL,
    channel TEXT NOT NULL,
    account_id TEXT,
    peer_id TEXT,
    guild_id TEXT,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    message_count INTEGER DEFAULT 0,
    last_message_at TIMESTAMP
);

-- 索引
CREATE INDEX idx_sessions_agent_id ON sessions(agent_id);
CREATE INDEX idx_sessions_updated_at ON sessions(updated_at);
CREATE INDEX idx_sessions_channel ON sessions(channel);
```

**字段说明：**

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| session_key | TEXT | ✓ | 主键，格式见下方说明 |
| agent_id | TEXT | ✓ | Agent ID |
| channel | TEXT | ✓ | 渠道（discord/telegram/slack） |
| account_id | TEXT | | 账号 ID |
| peer_id | TEXT | | 私聊对方 ID |
| guild_id | TEXT | | 群聊 Guild ID |
| created_at | TIMESTAMP | ✓ | 创建时间 |
| updated_at | TIMESTAMP | ✓ | 更新时间 |
| message_count | INTEGER | ✓ | 消息总数 |
| last_message_at | TIMESTAMP | | 最后消息时间 |

**session_key 格式：**
```
私聊: agent:{agentId}:{channel}:{accountId}:direct:{peerId}
群聊: agent:{agentId}:{channel}:{accountId}:guild:{guildId}
```

## 性能优化策略

### 1. WAL 模式

```sql
-- 启用 WAL 模式
PRAGMA journal_mode = WAL;

-- 优势：
-- ✅ 并发读：多个读者可以同时访问
-- ✅ 写入不阻塞读取
-- ✅ 性能提升约 30%
```

### 2. 批量写入

```typescript
// 批量插入使用事务
const insertMany = db.transaction((messages) => {
    const stmt = db.prepare(`
        INSERT INTO session_messages 
        (session_key, message_type, content, timestamp)
        VALUES (@sessionKey, @messageType, @content, @timestamp)
    `);
    
    for (const msg of messages) {
        stmt.run(msg);
    }
});

// 性能对比：
// 单条插入：100 条 ~ 500ms
// 批量插入：100 条 ~ 50ms (提升 10 倍)
```

### 3. 索引优化

```sql
-- 查询优化
SELECT * FROM session_messages 
WHERE session_key = ? 
ORDER BY timestamp DESC 
LIMIT 100;

-- 索引覆盖查询
CREATE INDEX idx_messages_session_time 
ON session_messages(session_key, timestamp DESC);
```

### 4. 数据清理

```typescript
// 定期清理旧数据（保留最近 30 天）
async cleanOldData(daysToKeep: number = 30) {
    const cutoffDate = new Date();
    cutoffDate.setDate(cutoffDate.getDate() - daysToKeep);
    
    // 删除旧消息
    await this.db.run(
        'DELETE FROM session_messages WHERE timestamp < ?',
        [cutoffDate.toISOString()]
    );
    
    // 删除空会话
    await this.db.run(
        'DELETE FROM sessions WHERE message_count = 0 AND updated_at < ?',
        [cutoffDate.toISOString()]
    );
    
    // 真空回收空间
    await this.db.exec('VACUUM');
}
```

-- 推荐配置
PRAGMA journal_mode = WAL;           -- 启用 WAL 模式

### C. 数据迁移策略

```typescript
// 数据库版本管理
const DB_VERSION = 1;

async init(config: SQLiteManagerConfig): Promise<void> {
    // 创建版本表
    await this.db.exec(`
        CREATE TABLE IF NOT EXISTS schema_version (
            version INTEGER PRIMARY KEY,
            applied_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
        )
    `);
    
    // 检查并执行迁移
    const currentVersion = await this.getVersion();
    if (currentVersion < DB_VERSION) {
        await this.migrate(currentVersion, DB_VERSION);
    }
}
```
